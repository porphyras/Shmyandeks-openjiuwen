# Навыки и инструменты для экономии токенов

## Что полезно именно этому харнессу

В стандарте [Agent Skills](https://agentskills.io/specification#progressive-disclosure)
подробная инструкция и ресурсы подгружаются по необходимости. Пакет сам по себе
не уменьшает расход: экономия появляется, когда код или нужный фрагмент инструкции
заменяет повторную генерацию большого текста.

У нас уже есть специализированные пути math/data/search/coding, короткие
промпты по типу задачи, локальная загрузка pandas, вычисления, проверка кода,
BM25 и детерминированный fast path. В текущем `Run` нет загрузчика SKILL.md;
простое добавление такого файла не изменит запросы модели. Документация
JiuwenSwarm про marketplace описывает другой слой интеграции и сама по себе
не подтверждает его доступность в закреплённом SDK openjiuwen 0.1.20.

По формуле соревнования выходной токен стоит в 10 раз больше входного.
Поэтому здесь проверяем небольшой инструмент, который уменьшает требуемый
ответ модели: точечное редактирование вместо переписывания целых функций.
Описание десятков инструментов и дополнительные ходы выбора навыка тоже
попадают в контекст; их стоимость нужно учитывать в A/B, а не считать бесплатной.

## Эксперимент: exact-edit tool

Включение: `HARNESS_CODE_EDITS=1`. По умолчанию выключен.

На первой попытке coding уровня 0 модель получает короткую инструкцию вернуть:

```json
[["result -= x", "result += x"]]
```

Для нескольких файлов допустимо `["pkg/core.py", "old", "new"]`. Название файла
должно точно совпадать с одним из исходников, переданных инструменту.

`harness/edits.py` применяет все изменения в памяти. Старый текст должен
однозначно совпасть, в том числе с учётом пересекающихся вхождений. Пустые,
неоднозначные, чрезмерные и синтаксически неверные изменения отвергаются до записи.
Входное отображение исходников не меняется при отказе. После записи харнесс
запускает прежние видимые тесты и проверки неизменности тестовых файлов.

При ошибке формата следующая попытка возвращается к полным функциям. При
синтаксически правильном, но неверном исправлении следующая попытка получает
реальный провал тестов. Готовый полный Python-ответ принимается и на первой
попытке. Общий лимит попыток не увеличивается; reasoning-повторы используют
прежний протокол. Вызовы моделей остаются в openJiuwen; native tool schemas,
MCP, новые сетевые сервисы и зависимости не добавлены.

## Что измерено

Набор: 100 задач генератора, seed 20261108, infeasible 0.2; 20 выполнимых coding.
Эталонные ответы получены из reference-файлов исключительно для офлайн-проверки.
Это не измерение того, насколько хорошо реальная модель умеет выбирать правки.

| Область | Полные функции с Python-обёрткой | JSON-пары | Сокращение символов ответа |
|---|---:|---:|---:|
| Все 20 coding-задач | 3994 | 3050 | 23,6% |
| 10 задач после бесплатного crossfix | 1829 | 1509 | 17,5% |

На всех 20 эталонных исправлениях оба протокола прошли видимые и скрытые тесты.
В первой строке JSON короче на 15/20 задачах; на остальных он длиннее.
Инструкция JSON-протокола добавляет **74 символа входа на первый запрос**.
Изначальный JSON с именованными полями old/new был даже длиннее текста функций
без Python-обёртки на 2,7%; компактный формат выбран после этого сравнения.

Эти проценты — не экономия оплаченных токенов. JSON иначе токенизируется,
инструкция стала длиннее, а ошибки выбора правок могут вызвать повтор.
Прежняя модель прогноза стоимости также не перекалибрована под новый режим.
Решение оставлено выключенным до реального A/B на независимых задачах.

## Воспроизведение офлайн

```bash
python3 bench/gen_tasks.py --out bench/sets/up1ng-audit --n 100 --seed 20261108 --infeasible 0.2
python3 bench/tools/bench_exact_edits.py --set bench/sets/up1ng-audit --verify
python3 bench/tools/bench_exact_edits.py --set bench/sets/up1ng-audit --after-crossfix --verify
python3 -m unittest discover -s tests -v
```

Скрипт меняет только временные копии. `--after-crossfix` учитывает существующие
бесплатные исправления, чтобы не приписывать новому инструменту их экономию.
При отсутствии задач для модели число задач в отчёте равно нулю.
Наборы и reference-файлы игнорируются Git и не попадают в Docker-образ;
новый модуль внутри `harness/` автоматически включается существующим Dockerfile.

28 тестов ветки проходят на Python 3.11.17 и 3.12.15 (macOS). Во временном
worktree проверено объединение с PR #2, #3 и #4: 60 тестов проходят на Python
3.12, отрицательные контроли из PR #3 обнаруживают 9/9 ошибок. В main эти ветки
при проверке не сливались.

## A/B на настоящем прокси

При настроенном окружении команды, на одном наборе и одной версии кода:

```bash
bench/run_local.sh bench/sets/up1ng-audit edits_off forward 100000 HARNESS_CODE_EDITS=0
bench/run_local.sh bench/sets/up1ng-audit edits_on forward 100000 HARNESS_CODE_EDITS=1
```

Нужно сравнить награду в `grade.json`, фактический `spent` в `stats.json`,
число повторов и hidden-test ошибки. Повторить на перефразированных и сложных
наборах. Генератор выше нужен для воспроизводимости механики, не для решения
включать режим на соревновании. Реальный API в этой работе не вызывался.
