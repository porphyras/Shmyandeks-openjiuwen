# Офлайн-проверки перед сдачей

Нужен Python 3.11 или 3.12, только стандартная библиотека. Не нужны API-ключи,
openJiuwen, pandas или установка `requirements.txt`.

```bash
python3 -m unittest discover -s tests -v
python3 bench/tools/check_test_sensitivity.py
```

Обе команды запускаются в GitHub Actions на Ubuntu с Python 3.11 и 3.12.
Тесты исключены из Docker-образа существующим `.dockerignore`.

## Проверяем не только готовые примеры

`test_metamorphic.py` генерирует 500 случаев с seed `20261108`: всего 1400
проверок результата. При падении unittest выводит seed и номер случая.
Ожидаемые отношения не извлекаются парсером решения:

- отправка N коробок в день D дней равна отправке N×D коробок;
- отправка и получение одного количества возвращают исходный запас;
- соседние запасы вокруг границы деления дают разные округлённые остатки;
- неизвестная операция после известных не должна молча исчезать;
- перестановка строк не меняет выручку, дублирование удваивает её,
  а строки другого региона не меняют выбранный итог;
- неуказанное правило округления на точной половине требует fallback;
- случайные имена файлов и посторонние карточки не меняют ответ по цепочке
  из 1–6 связей наставничества;
- изменение нужного факта Graz → Lima обязано изменить ответ.

## Обратные связи в базе знаний

`test_inverse_search.py` дополнительно проверяет обратные связи наставничества:
100 случайных графов (seed `20261109`), по четыре проверки — исходный ответ,
перестановка файлов с отвлекающим фактом, изменение конечного года и добавление
второго кандидата. Эталон вычисляется по целочисленным вершинам графа независимо
от текстового парсера. Отдельные случаи проверяют направление, область действия
фразы, алиасы, дубли, неоднозначность, неизвестные оговорки, лимиты чтения,
нечитаемые данные и симлинки. Это синтетическая регрессия, а не слепой набор.

## Прогоны со сбоями

`test_run_faults.py` запускает настоящий `Run.run()`, планировщик, solver,
файловые записи и subprocess-выполнение программ. Только LLM заменён
потокобезопасной заглушкой с заранее заданными ответами и ошибками:

1. Квота исчерпана после первого ответа: ответ уже есть на диске и в JSON,
   удалённая workspace-копия восстанавливается, новые запросы прекращаются.
2. Транспортная ошибка после ретраев клиента: другие задачи решаются,
   неудачная получает второй проход на reasoning-модели.
3. Программа модели падает: следующий запрос исправляет её, до этого
   `answer.txt` не появляется.
4. Инспекция одной задачи выбрасывает исключение: остальные продолжают работать.
5. Двадцать задач с пятью рабочими потоками: ответы, стоимости и итоговый
   JSON принадлежат своим задачам, резервы освобождаются.
6. Дорогая задача с большой наградой не помещается в бюджет: следующая дешёвая
   всё равно решается. Здесь прогноз стоимости задан тестом явно.
7. Пакет из 12 поисковых задач: 11 однозначных обратных связей дают ответы
   без LLM, одна неоднозначная доходит до клиента. Ответ заглушки проверяет
   маршрутизацию и запись файлов, а не способность модели разрешить неоднозначность.

Это проверки реакции харнесса на результат клиента, а не тесты HTTP,
openJiuwen rails, таймеров backoff или реального учёта токенов. Стоимость
успешного вызова заглушки — условная единица. SIGTERM/PID 1 и ограничения
Linux-контейнера остаются предметом отдельного Docker-прогона.

## Проверяем, что тесты умеют находить ошибки

`check_test_sensitivity.py` сначала запускает нужные тесты на обычном коде.
Затем в памяти процесса временно вносит двенадцать ошибок: неверный знак отгрузки,
ceil вместо floor, пропуск неизвестной фразы, потерю фильтра региона,
принудительное округление половины, пропуск звена KB-цепочки, постоянный ответ
вместо чтения факта, отключение восстановления ответов и отключение второго
прохода после транспортной ошибки; обратная связь, прочитанная в прямом направлении,
игнорирование второго ученика и использование обрезанной базы как полной.

Успех — все двенадцать изменений обнаружены assertion-проверками. Ошибка самого
теста не считается обнаруженным мутантом. Исходные файлы не редактируются,
патчи откатываются после каждого запуска. Это выбранные отрицательные контроли,
а не исчерпывающий mutation score и не оценка будущего конкурсного балла.
