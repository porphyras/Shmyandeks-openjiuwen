# Набор hard (bench/sets/hard)

Сложный оценочный набор из публичных бенчмарков в формате харнесса (раскладка как у `bench/sets/train_b`,
см. `bench/README_sets.md`). 116 задач: по 29 на тип, из них 25 выполнимых и 4 невыполнимых.
Номера `<type>_<NNNN>` сквозные, награда 1..5 равномерно и детерминированно (SHA-256 от метки).
Служебные фразы инструкций совпадают с примерами организаторов слово в слово (проверяется).

## Команды

```bash
D=/path/to/hard_dl          # загрузки; каждый источник в своей пустой папке (см. ниже)
python3 -I bench/hard/build_hard.py --dl $D     # ~1.5 мин, пишет только bench/sets/hard
python3 -I bench/hard/verify_hard.py            # ~10 с; пересчёт data через .venv/bin/python (pandas)
```

Загруженные файлы читаются только как данные (JSON/JSONL/CSV), все скрипты запускаются с `python3 -I`.
Код из загрузок не исполняется; исключение — эталонные решения MBPP, которые по заданию прогоняются
в песочнице (`sandbox_eval.py`: временная папка, `-I`, таймер 1 с на вызов, общий таймаут).
Сборка детерминирована: две сборки подряд дают побайтно одинаковый набор.

Загрузка (каждая в свою новую папку внутри `$D`):

## Как получены задачи

**math.** Текст задачи не меняется, добавляется только служебная фраза примеров.
- GSM8K: каждая аннотация калькулятора `<<expr=res>>` пересчитывается точной рациональной арифметикой
  (разбор AST, без исполнения кода), итог `#### N` должен быть целым и совпадать с результатом одной из аннотаций.
  Берутся задачи с наибольшим числом шагов (7–8).
- GSM-Hard: задача сопоставляется с исходной из GSM8K по тексту (порядок в файлах разный), в вопросе должно
  отличаться ровно одно число, встречающееся в оригинале один раз. Цепочка аннотаций GSM8K воспроизводится
  с подставленным числом (изменённые промежуточные результаты протягиваются дальше). Принимаются только задачи,
  где результат совпал с `target` GSM-Hard (два независимых вывода), ответ целый и положительный,
  промежуточные значения неотрицательны и остаются целыми там, где были целыми, и нет совпадений значений,
  делающих подстановку неоднозначной. Прошли 269 из 1319; взяты 13 самых многошаговых.
- Отброшены после ручного чтения: GSM8K 144 (имя героя меняется), 777 («only $6 of the cost»),
  814 (деньги: четвертаки или доллары), 690 («2/5 times more»), 1071 (считать ли именинницу гостем).

**coding.** Из 427 задач MBPP пригодны 270 (одна функция верхнего уровня, импорты только math/re/collections/
heapq/itertools/bisect/operator/string/functools, без print/open/eval и т. п., 25–260 узлов AST,
тесты — простые `assert`). Имена функций приведены к нижнему регистру, формулировка MBPP стала докстрингом.
Ошибки вносятся мутацией AST: неверное сравнение, сдвиг на единицу (`range`, индекс, срез), неверное начальное
значение, неверный оператор, `and`/`or`, `min`/`max`, неверная булева константа в `return`, `sorted(..., reverse=True)`.
Мутант годится, если он ломает хотя бы один assert MBPP значением, `IndexError`, `KeyError`, `ValueError` или
`ZeroDivisionError` (не `TypeError`, не зависание). В задаче 3–6 функций (MBPP-задачи и имена не повторяются
по всему набору), ошибок 1–3 (25 выполнимых: 6×1, 12×2, 7×3). Видимый тест — стиль примеров (`class T`, метод
на функцию), 1–2 assert MBPP, для каждой испорченной функции хотя бы один ломающийся. Скрытый тест — все assert
MBPP плюс до 2 дополнительных случаев на функцию: эталон на входах MBPP с сохраняющими структуру изменениями
(+1 к каждому элементу списка, без последнего элемента, n+1, n+2, строка без последнего символа); случаи
с float, недетерминированным результатом (два процесса) или зависанием мутанта отбрасываются, предпочтительны
случаи, которые мутант тоже ломает. `hidden/<id>/mylib_ref.py` — эталон.

**search.** Каждый из 20 абзацев элемента MuSiQue — файл `kb/<slug заголовка>.md` (`# Title`, пустая строка, текст).
Фильтры: ответ — год или имя собственное до 3 слов (без артикля, цифр, запятых), без alias, дословно есть
в опорном абзаце последнего шага и нет в вопросе; вопрос начинается с Who/What/Where/When/Which/In which/In what,
до 190 символов, без отношений с несколькими верными ответами (граничит, ребёнок, брат, супруг, участник группы…).
Вопросы «When …» с ответом-годом переписаны в «In what year …». Ответы и шаги декомпозиции не повторяются
внутри набора. Около 30 вопросов отброшено вручную (`EXCLUDE`, `BAD_ANSWERS` в `build_search.py`): искажённые
формулировки, несколько верных ответов, «Talca» против «Talca Province» и т. п. Порядок кандидатов — по SHA-256
от id, поэтому исключение одного вопроса не перетасовывает остальные.

**data_analysis.**
- DABench: из вопросов с одним целым или строковым ответом взяты 12 нетривиальных (выбросы по IQR с линейной
  интерполяцией квантилей, выбросы по z-оценке, argmax по группам с фильтрами, разбор строк вида
  `630308[495000-801000]`, подсчёт видов с ≥5 наблюдениями). Текст вопроса переписан из question+constraints
  так, чтобы определение было однозначным. Каждый ответ пересчитан стандартной библиотекой и совпал с меткой
  DABench; для z-оценок совпадают результаты при ddof=0 и ddof=1, для вопроса о брендах — при обоих прочтениях
  условия «не меньше 10 отелей». Пропущены тривиальные подсчёты пропусков и вопрос 59 (в данных Congo
  отнесено к региону Americas).
- Синтетика (CSV с CRLF, как у организаторов): клиника (patients+visits: квартал и год рождения, различные
  пациенты города, средняя стоимость визитов пациентов от 65 лет на дату визита; в половине вариантов
  названия отделений с разным регистром и пробелами), библиотека (просрочки > 21 дня по жанрам, выдачи в выходные
  книг до 1950 г., читатель с наибольшим числом разных книг за полугодие), рейсы (доля опозданий > 15 мин
  по перевозчику с порогом 30 рейсов, суммарная дистанция в выходные без опоздания, медианная задержка
  с округлением вниз, отменённые рейсы исключаются), кадры (больше своего руководителя — self-join, медиана
  зарплат по отделам), датчики (почасовые показания, исключение пропусков и показаний до установки датчика,
  выходные/часы). Ответ считает отдельный код по записанным CSV; argmax требует явного отрыва, округлённые
  значения не бывают близки к .5.

## Невыполнимые (16)

- math `vague_quantity`: в задаче GSM8K число, нужное решению, заменено на «some/several/a few/a number of»;
  воспроизведение цепочки с другим значением этого числа обязано менять ответ. (Удаление целого предложения
  пробовали и отказались: укороченные задачи часто оставались решаемыми.)
- data: `missing_column` (parking в hotel_data.csv), `absent_entity` (город Oslo, которого нет),
  `missing_file` (вопрос требует carriers.csv, файла нет), `absent_period` (март 2021, данные за 2023).
- search `musique_unanswerable`: неотвечаемые двойники MuSiQue (опорный абзац заменён), ответ и alias
  не встречаются ни в одном файле kb.
- coding: видимый тест содержит тот же вызов с другим ожидаемым значением (в том же методе или в `test_<f>_again`).

## Проверки (`verify_hard.py`)

- раскладка: в task.json ровно task_id/task_type/instruction/reward, id и награды, поля keys.json,
  `expected = null` у невыполнимых, у `exact_int` ответ — целое;
- служебные фразы равны фразам из `data/examples/task-dir`;
- search: ответ дословно есть в kb; у невыполнимых ответа датасета нет нигде;
- data: каждый ответ пересчитан второй раз на pandas (`verify_data_pandas.py`, параметры разбираются из текста
  инструкции), предпосылки невыполнимых проверены;
- coding: ошибочная mylib падает на видимом и скрытом тестах, эталон проходит оба (3 прогона, Python 3.14
  и 3.12 как в образе харнесса); у невыполнимых эталон падает только из-за строки-противоречия;
- прогон `bench/grade.py`: эталонные ответы — 100/100 выполнимых (297/297), без исправлений — 0.

## Замечания

- Ответы search верны относительно текста kb (например, «президент» или «лидер партии» на момент статьи).
- Скрытые дополнительные случаи coding получены от эталона MBPP: решение, переписавшее функцию с другим
  поведением на этих входах, скрытый тест не пройдёт (это и есть строгость скрытого теста).
- Длинные задачи GSM8K сложны рассуждением, а не арифметикой; сложность GSM-Hard — в больших числах.
